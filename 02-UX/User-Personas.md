# User Personas

## Overview

This document defines the primary user personas for BlihOps from a UX perspective. These personas guide user experience decisions, navigation, workflows, interface hierarchy, and feature prioritization throughout the design process.

While the PRD defines product requirements for each persona, this document focuses on how each user interacts with the platform and what they need to accomplish efficiently.

---

# Primary Persona

## Admin

### Description

Admins operate the entire BlihOps platform. They manage company leads, recruit and approve talent, onboard clients, maintain talent profiles, and oversee all operational workflows through the Admin Portal.

### Primary Goals

- Manage incoming leads
- Recruit and approve talent
- Onboard client companies
- Maintain talent profiles
- Keep operations organized

### Needs

- Fast operational workflows
- Clear recruitment pipeline
- Efficient data management
- Minimal repetitive actions
- High visibility across the platform

---

# Secondary Persona

## Client

### Description

Clients are approved company representatives invited to BlihOps. They use the Client Workspace to discover approved engineers, request interviews, monitor pilot progress, and organize hired talent into teams.

### Primary Goals

- Find suitable engineers
- Review talent profiles
- Request interviews
- Track pilot progress
- Organize hired engineers

### Needs

- Simple navigation
- Clear talent information
- Fast search and filtering
- Private workspace
- Minimal onboarding friction

---

# Secondary Persona

## Talent

### Description

Talents are approved software engineers with access to the Talent Portal. Their primary responsibility is keeping their professional profile accurate and up to date so it can be presented to potential clients.

### Primary Goals

- Maintain professional profile
- Update portfolio and resume
- Keep availability current
- Present accurate experience

### Needs

- Simple profile editing
- Fast file uploads
- Clear profile status
- Secure account access
- Minimal maintenance effort

---

# Shared UX Principles

Regardless of role, every user experience should prioritize:

- Speed over complexity
- Clarity over customization
- Consistency across workflows
- Minimal context switching
- Predictable navigation
- Immediate feedback for user actions

---

# Design Priority

Although BlihOps supports multiple user roles, every UX decision should prioritize the Admin experience first, as the Admin Portal is the operational center of the business.

Client and Talent experiences should remain focused, lightweight, and task-oriented, allowing users to complete their workflows with minimal friction while keeping operational control within BlihOps.
